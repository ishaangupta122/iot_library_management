## `Seat stays Reserved after returning from a break`

After the break button was pressed and the student sat down again, the
dashboard kept showing the seat as Reserved, because the ESP32 waits for
its 60-second return debounce before writing `1` back to the database.

## `Usage graphs empty after test sessions`

Sessions recorded while testing the sensors did not appear in the
analytics, because they took place after the library's Sunday closing
time and the graphs only count time inside opening hours.

## `Error: Failed to authenticate, have you run firebase login?`

Deploying the Firestore rules failed because the Firebase CLI was not
signed in; `firebase login` had been typed on the same line as the
install command, so it never ran.

## `Seat data blocked by Realtime Database rules`

The `sensors` read rule was set to `auth != null`, which blocked the
student page and kiosk from loading seat values because visitors are not
signed in, so the read rule had to be made public while writes stayed
restricted to the ESP32 account.
